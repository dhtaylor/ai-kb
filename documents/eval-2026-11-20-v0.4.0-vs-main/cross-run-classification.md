## User-reachable fixture patterns

Main's scripts import the `kbengine` package from the directory beside the script. Run in place, or through a symlink (verified: python resolves it), they work. A script copied ALONE somewhere fails at import, for kb-due, kb-libraries (and so kb-bootstrap, kb-library, kb-backup), check-kb, kb-verify, kb-watch, kb-sources, kb-report and the others now importing kbengine. Verified: `cp eng-main/scripts/kb-due /x/ && /x/kb-due` -> ModuleNotFoundError: No module named 'kbengine' (kb-due:85). In v0.4.0, kb-due copied alone worked and lost only the check-kb-dependent counts (its documented degrade, #30). Nobody documents copying as supported, and kb-session-start/kb-schedule resolve the engine by realpath, so a normal install is unaffected. kbengine/ is not mentioned anywhere in README/CLAUDE.md as something that must travel with the scripts (only CONTRIBUTING.md line 370 mentions kbengine.env).
